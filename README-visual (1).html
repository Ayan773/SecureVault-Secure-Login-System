01  About

About The Project

SecureVault is Project #4 in my web development journey — a fully functional secure login system implementing real-world security standards used by production applications.

Most tutorials show you how to build login forms. This project goes deeper — implementing the actual cryptographic primitives, attack mitigations, and security patterns that protect real user accounts.

The challenge: Build a complete authentication system with zero external dependencies, using only browser-native APIs — no bcrypt library, no JWT package, no auth framework.

The result: PBKDF2-SHA256 password hashing, TOTP-based 2FA, rate limiting, CSRF protection, session management, and input sanitization — all from scratch.

03  Features

What's Included

🔑

Password Hashing

PBKDF2-SHA256 with 100,000 iterations and unique salt per user — equivalent to bcrypt cost 12.

📱

Two-Factor Auth

TOTP (RFC 6238) built from scratch. Works with Google Authenticator, Authy, and Bitwarden.

🚫

Rate Limiting

Account lockout after 5 failed attempts with a 30-second cooldown per username.

⏱

Session Management

Cryptographic session tokens with 30-minute sliding expiry and instant logout.

🕵

Timing Attack Prevention

Always hashes on login — even for invalid usernames — preventing enumeration via response time.

🛡

CSRF Protection

Cryptographically random CSRF token generated and bound to each active session.

✓

Input Validation

Real-time validation with XSS character stripping on all inputs before any processing.

📊

Security Dashboard

Post-login dashboard showing security score, session token, activity log, and 2FA status.

How It Works

Password Hashing (PBKDF2)

🔐 password-hashing.js
// Each user gets a unique 24-byte cryptographic salt
const salt = generateSalt(); // crypto.getRandomValues()

// PBKDF2 with 100,000 iterations
const hash = await crypto.subtle.deriveBits({
  name: "PBKDF2", salt, iterations: 100000, hash: "SHA-256"
}, keyMaterial, 256);

Two-Factor Auth (TOTP / RFC 6238)

📱 totp.js
// counter = floor(unix_timestamp / 30 seconds)
const counter = Math.floor(timeStep / 30);

// HMAC-SHA1(secret, counter) → dynamic truncation → 6 digits
const key = await crypto.subtle.importKey(
  "raw", base32ToBytes(secret),
  { name: "HMAC", hash: "SHA-1" }, false, ["sign"]
);

Timing Attack Prevention

⏱ anti-timing.js
// WRONG: attacker times response to detect valid usernames
if (!user) return error(); // fast → username leaked!

// CORRECT: always hash, even for unknown users
if (!user) await hashPassword(password, 'dummysalt');
const hash = await hashPassword(password, user.salt);
if (hash !== user.hash) return error(); // identical timing

10  Learnings

What I Learned

01

Crypto is Nuanced

PBKDF2 is not just "hash + salt." Iteration count, salt entropy, and output length all materially affect security strength.

02

Timing Attacks Are Real

Response time differences of milliseconds can leak whether a username exists. Constant-time comparison is non-negotiable.

03

2FA Is Just HMAC

TOTP is HMAC-SHA1 of a secret key and a time-based counter — nothing magic. Building it from scratch was genuinely satisfying.

04

Defense in Depth

No single measure is enough. Hashing + 2FA + rate limiting + sanitization together create real, layered security.

05

Browser Crypto Is Powerful

The Web Crypto API does PBKDF2, HMAC, AES, RSA natively — no library needed. The browser is a crypto powerhouse.
